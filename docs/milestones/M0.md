# M0: Project Setup & AI-Assisted Development

## Goal

Make Claude Code a first-class development tool for this repository: port the configuration
from the reference project (CLAUDE.md, settings, hooks, agents, skills, MCP servers) and the
GitHub automation around it, adapted to this stack (Go Fiber API, Go worker, React, PostgreSQL,
Redis, RabbitMQ, ClickHouse, Kubernetes) and to this roadmap, and land it on `dev` so M1 starts
from a working setup.

Most of the work already exists as uncommitted files on a local `dev` checkout. M0 turns it
into reviewed PRs, fills the gaps (MCP servers, labels) and closes the milestone.

## Exit criteria

1. `origin/dev` contains `CLAUDE.md`, `.claude/settings.json`, `.claude/hooks/*.sh`,
   `.claude/agents/reviewer.md` and the six skills (`fix-issue`, `milestone-status`,
   `plan-milestone`, `release`, `ship`, `start-issue`), plus `.github/` and `scripts/`.
2. `.claude/settings.json` is valid JSON against its schema and has no one-off or duplicate
   permission entries and no machine-specific absolute paths.
3. Every hook script is executable and exits 0 when given a no-op payload on a repo with no
   `go.mod`, `Makefile` or `sqlc.yaml` (verified with
   `echo '{}' | CLAUDE_PROJECT_DIR=$PWD .claude/hooks/<hook>.sh`).
4. `before-bash.sh` exits 2 for `kubectl apply -f x.yaml` and 0 for
   `kubectl --context kind-heimdall apply -f x.yaml`; `before-edit.sh` exits 2 for `.env` and
   `internal/store/db/x.go`.
5. `bash scripts/eng-issue_test.sh` passes.
6. On a test PR into dev, `pr-conventions` fails for a title without "(ENG-<n>)" and passes for
   a conforming one; `claude-code-review` runs on a PR into dev; merging a `chore/ENG-<n>-*`
   PR closes ENG-<n> through `close-issue`.
7. MCP servers are either configured in a committed `.mcp.json` and listed by `claude mcp list`,
   or explicitly dropped with a dated line in Decisions.
8. The labels used by the plan-milestone skill exist in the repo.
9. `/milestone-status M0` reports every M0 issue as done and no scope creep.

## Risks

- **Workflow bootstrap.** Workflows triggered by `pull_request` on dev only behave as expected
  once they are on dev; the 0.1a PR itself is not checked by them. Mitigation: merge 0.1a first
  and close its issue by hand if `close-issue` does not fire.
- **MCP servers as dependencies.** Each MCP server is a new external dependency (npm/uvx
  package or remote endpoint), which CLAUDE.md says needs approval. Mitigation: 0.1c does not
  start until Open question 1 is answered.
- **Hooks that fail open.** The hooks skip their checks until M1 adds `go.mod`, `Makefile` and
  `sqlc.yaml`; a typo there could silently disable them later. Mitigation: exit criteria 3–4
  now, and re-check the hooks when M1 adds the Makefile.

## Open questions
