# M1: Infrastructure Core & Authentication

## Goal

Stand up the foundation every later milestone builds on: a Go module with `make check` running
in CI, a local Docker Compose stack (PostgreSQL, Redis, Keycloak), a Keycloak realm with clients
for the web app and the API, a Fiber API that rejects any request without a valid Keycloak JWT,
the core PostgreSQL schema behind sqlc, a Redis cache-aside layer, and a React app where a user
can log in. End-to-end, logging in on the web app and calling `GET /api/v1/me` creates that user
in PostgreSQL.

## Exit criteria

1. `make check` passes on a clean `origin/dev` checkout with no services running. It runs
   golangci-lint, `go test ./...`, the `make generate` diff check, the web lint/typecheck/test,
   `scripts/*_test.sh` and `.claude/hooks/hooks_test.sh`.
2. The `ci` workflow runs `make check` on every PR into dev and fails the PR when it fails.
3. `make up` starts PostgreSQL, Redis and Keycloak, and all three report healthy in
   `docker compose ps`. `make down` removes them, and `make down` followed by `make up` gives
   the same realm and an empty database.
4. The `heimdall` realm is imported on startup and contains the `heimdall-web` client (public,
   PKCE S256, redirect `http://localhost:5173/*`) and the `heimdall-api` audience. A token issued
   to `heimdall-web` has `aud` containing `heimdall-api`. Checked by an integration test.
5. API unit tests (local RSA keys and an `httptest` JWKS server) show `/healthz` returns 200
   with no token, and that every other route returns 401 for: a missing token, a malformed
   header, an expired token, the wrong issuer, the wrong audience, an unknown `kid` and a bad
   signature. A valid token gets 200. An integration test gets the same 200/401 split using a
   real Keycloak token.
6. `goose` migrations run up, all the way down and up again against an empty PostgreSQL
   (integration test). They create `users`, `projects`, `project_members`, `pipelines`,
   `executions` (UUID primary key) and `allowed_images`, with foreign keys and indexes.
7. `make generate` gives no diff on dev, and `internal/store/db` is produced only by sqlc. Store
   integration tests cover every query.
8. Cache-aside unit tests (fake Redis) show a miss calls the store and fills the cache, a hit
   does not call the store, entries expire after their TTL, invalidation drops the entry, and
   when Redis is down reads fall back to the store with an error log. One integration test does
   the same against the Compose Redis.
9. `/readyz` returns 503 while PostgreSQL or Redis is unreachable, and 200 when both are up.
10. In the web app, `npm run lint`, `npm run typecheck` and `npm test` are clean. An
    unauthenticated visit redirects to Keycloak; after login the page shows the user returned by
    `GET /api/v1/me`; logout ends the Keycloak session.
11. Manual end-to-end check (`make up`, the API and `npm run dev`): the first login creates one
    `users` row keyed by the token `sub`, and a second login does not create another.
12. With `go.mod`, `Makefile` and `sqlc.yaml` in place, the hooks actually run: `after-edit.sh`
    reports a lint error in a `.go` file, and `stop-check.sh` runs `make check`.
    `hooks_test.sh` covers both.
13. CLAUDE.md's Commands and Architecture sections match what landed.
    `/milestone-status M1` reports every M1 issue as done and no scope creep.

Item details:

- **1.0** (not in the roadmap; see Decisions) creates `go.mod`
  (`github.com/MagnunAVF/heimdall-actions`, current stable Go) with `sqlc` and `goose` as
  `go tool` dependencies, plus `.golangci.yml` and a `Makefile` with every M1 target: `check`,
  `lint`, `test`, `test-integration`, `generate`, `up`, `down`. Targets whose inputs do not
  exist yet are skipped with a message, in the same way the hooks fail open, so later issues
  never edit the Makefile. It adds `.github/workflows/ci.yml` (actions pinned to SHAs) to run
  `make check`, and `internal/platform/{errs,config,obs}`: sentinel errors, env-only config
  loading with validation, and a slog JSON logger. After merge, `ci` and `pr-conventions` are
  made required checks on dev. Acceptance: exit criteria 1–2.
- **1.1a** adds `infra/local/docker-compose.yml` with pinned images, healthchecks, named volumes and
  no secrets (dev-only defaults through `${VAR:-default}`), plus `infra/local/.env.example`.
  Acceptance: exit criterion 3, except the realm.
- **1.1b** adds `infra/local/keycloak/heimdall-realm.json`, imported on start. It defines the
  `heimdall-web` client (public, PKCE, local redirect and web origins), the API audience (an
  audience mapper on `heimdall-web`), realm roles `admin` and `developer`,
  and two dev users with known dev-only passwords. Acceptance: exit criterion 4.
- **1.2a** adds `cmd/api` (flags, config, wiring) and `internal/api` (Fiber app, `/healthz`,
  a `/readyz` stub, request logging with slog, recover middleware, graceful shutdown on
  SIGTERM). Acceptance: `/healthz` unit test; the process shuts down cleanly in under 5 s.
- **1.2b** adds JWKS fetching with caching and key rotation, and validation of signature, `iss`,
  `aud`, `exp`/`nbf` (small clock skew allowed) and algorithm (RS256 only). Every route except
  `/healthz` and `/readyz` sits behind it, and verified claims go into the request context.
  `GET /api/v1/me` returns the claims for now. Acceptance: exit criterion 5.
- **1.3a** adds `internal/store/migrations` (embedded) and `store.Migrate(ctx, dsn)`. Tables:
  `users` (keyed by Keycloak `sub`), `projects`, `project_members` (role), `pipelines`,
  `executions` (UUID, status enum `pending|running|succeeded|failed`, timestamps) and
  `allowed_images`. Acceptance: exit criterion 6.
- **1.3b** adds `sqlc.yaml`, `internal/store/queries`, generated `internal/store/db`, the pgx
  pool constructor, a `WithTx` helper and a `Store` interface. Queries: upsert user by `sub`,
  get user, create/get project, add member, get member role, list allowed images, create/get
  execution. Acceptance: exit criterion 7.
- **1.4a** scaffolds `web/` as a deliberately small app (the project's focus is backend and
  infra): Vite, React and strict TypeScript, Bootstrap (CSS only), ESLint and Prettier, Vitest
  with React Testing Library, React Router with a layout and a 404 page, and a Vite dev proxy
  from `/api` to the API. The data-fetching layer is a typed `src/api` module (one `fetch`
  wrapper) plus a small `useApi` hook (loading/error/data). It has no query library and no
  Redux. Acceptance: lint, typecheck and tests are clean in CI through `make check`.
- **1.4b** adds `keycloak-js` (authorization code with PKCE), a small auth context, a
  protected-route wrapper, token refresh before expiry, logout, and the bearer token on every
  `src/api` call. It adds a `/me` page that uses `useApi`. Tests mock `keycloak-js` and the
  `src/api` module with `vi.mock`. Acceptance: exit criterion 10.
- **1.5** adds `internal/cache`: the go-redis client constructor, a generic cache-aside helper
  (JSON codec, TTL, invalidate, fail-open reads to the source with a logged error), and typed
  caches for `AllowedImages` and `ProjectRole(user, project)` on top of the 1.3b `Store`
  interface. These caches have no HTTP consumers until M2. Acceptance: exit criterion 8.
- **1.2c** wires the pgx pool, migrations (behind a `--migrate` flag), the Redis client and both
  caches into `cmd/api`. It makes `/readyz` check PostgreSQL and Redis, and makes `/api/v1/me`
  upsert the user from verified claims and return the stored row. Acceptance: exit criteria 9
  and 11.
- **1.6** updates CLAUDE.md (Commands, Architecture: "planned" becomes what exists), extends
  `hooks_test.sh` for exit criterion 12, and changes "Current focus" once M1 closes. Acceptance:
  exit criteria 12–13.

## Risks

- **Shared `go.mod`.** Every Go issue adds dependencies. Mitigation: rebase on dev and run
  `go mod tidy` to resolve conflicts in `go.mod`/`go.sum`. Never hand-merge `go.sum`.
- **Fail-open Makefile targets.** Like the hooks, targets that skip when inputs are missing
  could hide a broken check later. Mitigation: 1.6 removes the skips once every input exists,
  so `make check` fails if `sqlc.yaml` or `web/package.json` go missing.
- **Keycloak audience.** By default a public client's token does not carry the API audience, so
  1.2b would reject every real token. Mitigation: 1.1b's exit criterion 4 asserts `aud` before
  1.2b starts its integration test.
- **Keycloak startup time** in `make up` (30–60 s) slows integration tests. Mitigation:
  healthcheck plus `docker compose up --wait`, and no Keycloak in `make check`.
- **Many new dependencies at once.** CLAUDE.md requires approval for each. Mitigation: the
  approved list is under Open questions. Nothing outside it is added without asking.
- **Parallel lanes, one reviewer.** Up to three PRs a day may overload review. Mitigation: the
  schedule keeps at most three lanes active on any day, and there are 4 days of buffer.
